# env_builder エージェント基本指示

このリポジトリは、手元PC（Windows / Python）から踏み台越しに SSH 接続し、
**参照元サーバ(src)を参考に構築先サーバ(dst)の環境を整える**ための作業基盤である。
思想は Ansible 的（宣言的・インベントリ）だが、環境を整える探索フェーズに合わせて
「汎用スクリプト + エージェント制御」で実現する。

このドキュメント配下（`.agent/`）は、どのエージェントツール（Kiro / Claude Code /
Codex / Antigravity 等）でも解釈できる**ツール非依存の知識ベース**である。ルール・手順・
スクリプト説明はすべてここに集約し、各ツールからはポインタ経由で参照する。
ツールごとの差異は「ツール・環境による差異（読み替え）」を参照。

## エージェントの役割

- **スクリプトは手順の方針**であり、実行判断はエージェントが行う。どのスクリプトを
  どの順で叩くか、出力をどう解釈して次に何をするかは、状況を読んでエージェントが決める。
- スクリプトは「引数を変えれば別状況でも使い回せる機械的処理」を担う。エージェントは
  「状況を読んで決める判断・解釈・順序」を担う。この境界は `references/scripts.md` を参照。
- 作業対象は build に限らない。ビルド疎通、コンテナ環境の構築など、「src を参考に dst の
  環境を整える」作業全般を扱う。

## 基本姿勢

- **探索 → 計画 → 実装** の順で進める。複数ファイルにまたがる変更や不慣れな箇所は、
  先に調査・計画してから実装する。
- 同じ修正を 2 回以上繰り返しても解決しない場合は、対症療法をやめて根本原因を診断し、
  異なるアプローチを取る。
- 破壊的・不可逆な操作（リモートの削除、広範囲な変更）は事前に影響を説明し、確認を取る。
- 作成・更新するファイルは UTF-8（BOM なし）/ 改行コード LF とする。

## まず読むべきファイル

作業に入る前に、状況に応じて以下を読み込んで準拠すること。

- **運用の鉄則**: `.agent/rules/operation-safety.md`（最重要。sudo/su 禁止など）
- **Git 運用**: `.agent/rules/git-workflow.md`
- **コーディング規約**: `.agent/rules/coding-style.md`
- **スクリプト仕様と境界**: `.agent/references/scripts.md`
- **全体フロー**: `.agent/references/workflow.md`
- **各種ワークフロー手順**: `.agent/skills/<name>/SKILL.md`

## ツール・環境による差異（読み替え）

どのツールでも同じ手順で使えるよう、ツール依存の点は次のように読み替える。

- **SKILL.md の `allowed-tools`**: Claude Code 形式のツール名（`Bash` / `Read` / `Grep` /
  `Glob`）。他のツールでは無視される。「その手順で使う操作の種類（コマンド実行・
  読み取り・検索）」の目安として読む。
- **スキルの自動検出**: `.agent/skills/` はツールによって自動検出されない（特に Claude Code）。
  必要な手順は `SKILL.md` を自分で開いて読む。一括読込は `context` スキルを使う。
- **コード例のシェル**: 例は Windows の PowerShell 構文（`$env:NAME = "..."`、行継続の
  バッククォート、`cmd /c "call set_env.bat && ..."`）。WSL / Linux / macOS のエージェントは
  次のように読み替える。コマンド本体（`uv run python -m env_builder ...`）は共通。
  - 環境変数: `export NAME="..."`、解除は `unset NAME`
  - 行継続: バックスラッシュ `\`
  - 一時ディレクトリ: `$TMPDIR`（未設定なら `/tmp`）
  - `set_env.bat` は Windows 用。Linux では同等の環境変数を `export` で渡す
- **承認が必要な操作**: 承認 UI のないツールや自動実行設定でも、内容と影響をユーザーに提示して
  応答を待つ。承認があるものとみなして進めない。

## 案件固有のメタデータ

「今どのモジュールを・どのサーバで・どう構築するか」といった案件ごとの可変情報は、
`.agent/` には置かず、Git 管理外の設定に置く。

- 接続対象の定義: `inventory/servers.json`（機密。環境変数でパスワードを渡す）
- あるべき状態の定義: `desired_state/`（build ターゲット、パッケージ、ファイル対応表など）
- 作業成果物・ログ: `build_env/`

`.agent/` の手順書はこれらを「読んで判断せよ」と参照する。手順そのものは普遍化して
`.agent/` に置き、案件差はメタデータの差し替えで吸収する。
