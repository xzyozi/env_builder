# 転送前の事前チェック（容量）

src から dst へデータを運ぶ前に、配置先の空き容量を確認する。基準を満たすときだけ転送し、
満たさない・測れないときは転送せずに止まる。この確認がコード側にあるため、転送コマンドは
エージェントが承認待ちなしで実行できる（権限設定は `.kiro/agents/project-initializer.md`）。

## 基準

配置先の空きが、**転送データのサイズ + 1 GiB** 以上あること。

| 項目 | 内容 |
| --- | --- |
| 転送データのサイズ | src で `du -sbc -- <対象>` を実行した合計（バイト）。読み取れないファイルがあって `du` が失敗したときは、過小に見積もらないよう不合格にする |
| 配置先の空き | dst で `df -Pk` を実行した「空き」。配置先がまだ存在しないときは、存在する最も近い親ディレクトリのファイルシステムを調べる |
| 余裕 | 1 GiB（`env_builder/ops/capacity.py` の `RESERVE_BYTES`） |
| 配置先が複数（files.json） | 配置先ごとに、全データ分 + 1 GiB の空きを要求する（同じファイルシステムでも安全側に倒す） |
| 境界 | 空きがちょうど「サイズ + 1 GiB」なら合格。1 バイトでも下回れば不合格 |

## 対象

| コマンド | 容量チェック |
| --- | --- |
| `sync_tree`（`uv run python -m env_builder sync_tree` / `scripts/sync_tree.py`） | あり。`--remote-src` の合計サイズと `--remote-dst-parent` の空き |
| `sync_files`（files.json に従う転送） | あり。各 `src_path` の合計サイズと、各 `dst_path` の親ディレクトリの空き |
| `sync_files --upload-only` | なし。src を使わず、手元のファイルを送るだけのため |

## 不合格・測定不能のとき

- 転送を始めず、作業領域（ローカル・リモートとも）も作らずに、終了コード 1 で終わる。
- 理由（必要量・空き・対象パス）はログに出る。空きを確保してから再実行する。
- 確認を飛ばすオプションはない。

チェックでリモートに送るコマンドは `du` と `df` だけで、src・dst のどちらの状態も変えない。

## 自動で実行してよい範囲（エージェント）

- src は読み取りのみ。書き込み・削除・移動はしない（`operation-safety.md`）。
- dst への配置は、転送スクリプトによるコピー（展開）に限る。
- 次は自動にせず、提示して応答を待つ。
  - root 定義（`src_root` / `dst_root`）を使う転送
  - `--upload-only`
  - 削除、既存ファイルの上書きを伴う操作
  - `ssh` / `scp` の直接実行（容量チェックを通らないため）

## まだ見ていないもの

- dst の `/tmp` 作業領域の空き（`tree.tar.gz` を置く場所）。配置先と別のファイルシステムだと、ここで
  不足して転送が途中で失敗することがある。失敗しても作業領域は cleanup される。
- ローカルの中継領域（`build_env/work/<work-id>/stage/`）の空き。
- inode の残り、書き込み権限。
- 展開先にすでにあるファイルの上書き。`tar xzf` は同名のファイルを上書きする。
