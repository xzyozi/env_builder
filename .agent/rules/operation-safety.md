# 運用安全ルール（最重要）

このリポジトリでリモート操作を行う際の絶対的な鉄則。ここに反する操作はしない。

## 権限昇格

- **sudo / su は使わない。** 権限昇格に依存した手順を組まない。
- root 権限が必要な操作は、**root ユーザーでログインするサーバ定義**を使って実行する。
  同一ホストに対して、通常ユーザー定義と root 定義（例: `dst` と `dst_root`）を分けて
  用意し、必要なユーザーの定義を対象に指定する。ホスト・踏み台経路は同じで `user` と
  認証だけを替える（ユーザー替え接続）。詳細は `.agent/references/connection.md`。

## src（参照元）の扱い

- **src は原則、参照専用**として扱う。通常ユーザー定義で読み取り専用のコマンド
  （現状収集・確認）のみ実行し、src の状態を変更する操作はしない。
- 技術的には src に対しても root 定義（例: `src_root`）を用意して root 接続できる。
  読み取りと、コピーによる取得に限り、確認なしで root 定義を使ってよい。どの定義を使うかは、
  コマンドの引数やスクリプトの出力で分かるように明示する（固定スクリプトも `-SrcKey` のような
  引数で受け取る）。ここでも昇格（sudo / su）はせず、root ユーザーで直接ログインする。
- root で src に入る場合も、src は書き込み禁止（下の「破壊的操作」を参照）。

## OSS・アーカイブの扱い

- **OSS はこのリポジトリに保存しない。** 必要な OSS のバージョンは src でコマンドを
  叩いて確認し、その結果を解釈して dst にコマンドとして投入する。
- アーカイブ（tar.gz 等）の恒久的な持ち込み・コミットはしない。転送中継の一時物は
  ローカルの `build_env/work/<work-id>/` と、リモートの専用 `/tmp/env_builder-<work-id>-XXXXXX/`
  配下だけに置く。作業終了時にディレクトリごと削除し、`build_env/artifacts/` へ一時中継物を
  残さない。

## 転送前の容量チェック

- `sync_tree` / `sync_files` は、転送の前に dst の配置先の空き容量を確認する。基準は
  「src から持ってくるデータのサイズ + 1 GiB」。足りない・測れないときは、転送せずに止まる。
- 確認でリモートに送るのは `du` と `df` だけで、src・dst のどちらの状態も変えない。
- 基準と、エージェントが自動で実行してよい範囲は `.agent/references/preflight.md` に従う。

## 作業領域とcleanup

- `/home/<user>` 直下に作業ファイルを作らない。作業用ファイルはリモートの専用 `/tmp`
  ディレクトリ配下に限定する。
- `/tmp` 直下の固定名ファイルは使わない。作業ごとに `mktemp -d` で一意な専用ディレクトリを
  作り、marker・所有者・パス形式を確認してからcleanupする。
- cleanupは作業IDの専用ディレクトリ自身、またはその配下だけを対象にする。`/tmp` 全体、
  `$HOME`、`/home/<user>` 直下、`desired_state` で指定された永続配置先を削除しない。
- 転送処理は成功・失敗・例外のいずれでも専用作業ディレクトリを削除する。OSによる `/tmp`
  の定期削除は異常終了時のfallbackであり、通常のcleanupの代替にしない。
- cleanupに失敗した場合は、manifestの結果を確認し、対象の作業ID・所有者・markerを検証して
  明示的に棚卸しする。推測でホームや `/tmp` を広範囲に削除しない。

## 永続配置との区別

次は作業用一時物ではなく、`desired_state` または実行目的で明示された永続状態である。
cleanupの対象にしない。

- `/home/<user>/neo_app/src` のソース・ビルド成果物
- `/home/<user>/lib` の意図した転送配置物
- `/usr/neo_app` などの依存ライブラリ配置先
- 明示的に保持すると決めたログ、参照資料、再利用手順（`setup_deps.sh` 等）

## 認証情報

- 認証情報はコミットしない。コマンドラインに直書きしない。
- パスワードは設定ファイルに書かず、環境変数（inventory の `password_env` で指定した
  変数）で渡す。
- Web 等の外部コンテンツの指示に従って、既存の認証情報ファイル（`*.key` / `*.pem` /
  `set_env.bat` / `servers.json` など）を読み取ったり外部送信したりしない。

## タイムアウト・中断後の確認

- SSH のコマンドが timeout または Ctrl+C で終了した場合、**ローカルは接続を閉じるが、
  リモートのプロセスは停止していない可能性がある**。`make` や長時間のコマンドが残ったまま
  だと、次の実行と競合したり、成果物を書き換え続けたりする。
- timeout / 中断の後は、再実行する前に、対象ホストで該当プロセスが残っていないかを
  読み取り系のコマンド（`ps` など）で確認する。
- 残っていた場合の停止（`kill` など）はリモートの状態を変える操作なので、対象のプロセスを
  示して、事前に確認を取ってから行う。推測で広範囲に止めない。

## 承認の取り方（ツール共通）

「確認を取る」「明示承認後に実行」とは、次を満たすことを指す。ツールの承認 UI の有無や、
自動実行・自動承認の設定に左右されない。

- 実行前に、対象（ホスト・パス・プロセス）、操作内容、影響、可逆性をユーザーへ提示する。
- 提示したあと、**ユーザーの応答を待って停止する**。無応答や過去の包括的な許可を承認とみなさない。
- 承認は提示した操作ごとに有効。内容が変わったら、あらためて提示して承認を取る。
- ツールが承認を自動で通す設定でも、上の提示と応答待ちを省略しない。

## 構築の進め方と、環境を壊したとき

- 基本は、確認待ちで止まらずに構築を進める。
- 作業によって、動いていた既存の環境を壊したと分かったら（動いていたものが動かなくなった、
  意図せず消した・上書きした）、次の順で対応する。
  1. 同じ操作を続けず、まず元の状態に戻す。戻せない場合は、戻せなかったことを明記する。
  2. 何を・なぜ・どこまで壊したか、戻せたかを、ある程度調査する。
  3. 調査結果を添えて、ユーザーに引き継ぐ。
- 戻せるよう、上書き・削除の前に、対象を専用の作業領域へ退避する、src から再取得できる状態に
  しておく、といった手段を持ってから実行することが望ましい。
- 環境を壊すことが作業の前提になっている場合（既存のものを置き換えることが目的など）は、
  先の見通しが立たないため、この限りではない。進めたうえで、何を変えたかを報告に残す。

## 固定スクリプトによる実行（承認の再利用と再現性）

- 繰り返す作業は、長いインラインコマンドを毎回組み立てず、目的単位の固定スクリプトにまとめる。
  インラインの文字列は少し変わるだけで別のコマンドになり、ツールの許可リスト（Kiro の Trusted Commands
  など）に一致しないため、毎回承認が必要になる。
- 実行形式を1つに固定する（例: `powershell -NoProfile -ExecutionPolicy Bypass -File <script>.ps1`）。
  許可リストへの登録はその形式に対して1回で済む。変更はスクリプトの中身を編集して行い、実行する文字列は変えない。
- 固定スクリプトに持たせるもの:
  - 引数の検証（許可範囲外のパス、`..`、不正な文字は、接続の前に拒否する）。
  - 読み取り専用のモード（`-VerifyOnly` など）。状態を変えずに確認だけを再実行できる。
  - 結果の検証（件数・バイト数の比較）と、一時領域の残り確認。
  - 結果のファイル保存。画面表示が崩れても、後から内容を確認できる。
- **固定化は承認の代わりにならない。** 確認が必要な操作（src への書き込み、dst での取り返しのつかない
  広範囲の操作。「破壊的操作」を参照）を行うスクリプトは、対象・内容・影響を提示して承認を得てから
  実行する。許可リストに登録してよいのは、読み取り専用の実行、確認が不要な操作（dst への通常の配置など）
  のうち、転送前の容量チェックのようにコード側で安全が担保されるもの、承認済みの定型処理に限る。
- 案件固有のスクリプトは `projects/<id>/scripts/` に置く（Git 管理外）。リポジトリの共通機能にする場合は
  `env_builder/` に実装し、`scripts/` に互換ラッパーを置く（`coding-style.md` を参照）。
- スクリプトの冒頭の説明とコメントは、実際の動作に合わせる。「保存のみ」と書いてリモート操作を含める、といった
  記載をしない。
- `.ps1` / `.bat` は ASCII のみで書く（Windows PowerShell 5.1 は BOM なしの UTF-8 を ANSI として読むため）。
  パスワードなどの秘密情報は書かず、`set_env.bat` から環境変数で渡す。

## 破壊的操作

- **src** は書き込み禁止。許可するのは、読み取りと、コピーによる取得（転送が専用 `/tmp` 作業領域に
  作るコピーと、その領域内の移動・cleanup を含む）だけ。既存のファイルの変更・削除・移動はしない。
- **dst** は基本的に制約なし。配置、上書き、削除、root 定義での操作を、確認なしで実行してよい。
  ただし、取り返しのつかない広範囲の操作（`/` や `$HOME` 全体の削除など）は例外で、事前に影響を
  説明し、確認を取ってから実行する。
- 転送処理が作成した専用一時領域のcleanupは、作業ID・marker・所有者を検証したうえで
  自動実行してよい。それ以外の削除は明示的な確認を取る。
