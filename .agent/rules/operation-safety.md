# 運用安全ルール（最重要）

このリポジトリでリモート操作を行う際の絶対的な鉄則。ここに反する操作はしない。

## 権限昇格

- **sudo / su は使わない。** 権限昇格に依存した手順を組まない。
- root 権限が必要な操作は、**root ユーザーでログインするサーバ定義**を使って実行する。
  同一ホストに対して、通常ユーザー定義と root 定義（例: `dst` と `dst_root`）を分けて
  用意し、必要なユーザーの定義を対象に指定する。ホスト・踏み台経路は同じで `user` と
  認証だけを替える（ユーザー替え接続）。詳細は `.agent/references/connection.md`。

## src（参照元）の扱い

- **src は原則、参照専用**として扱う。通常ユーザー定義で読み取り専用のコマンド
  （現状収集・確認）のみ実行し、src の状態を変更する操作はしない。
- 技術的には src に対しても root 定義（例: `src_root`）を用意して root 接続できる。
  root 権限が要る参照・確認が必要なときは、その理由を明示したうえで root 定義を
  対象に指定する。ここでも昇格（sudo / su）はせず、root ユーザーで直接ログインする。
- root で src に入る場合も、既定は**状態を変えない**こと。変更が必要なときは事前に
  影響を説明して確認を取る。

## OSS・アーカイブの扱い

- **OSS はこのリポジトリに保存しない。** 必要な OSS のバージョンは src でコマンドを
  叩いて確認し、その結果を解釈して dst にコマンドとして投入する。
- アーカイブ（tar.gz 等）の恒久的な持ち込み・コミットはしない。転送中継の一時物は
  ローカルの `build_env/work/<work-id>/` と、リモートの専用 `/tmp/env_builder-<work-id>-XXXXXX/`
  配下だけに置く。作業終了時にディレクトリごと削除し、`build_env/artifacts/` へ一時中継物を
  残さない。

## 作業領域とcleanup

- `/home/<user>` 直下に作業ファイルを作らない。作業用ファイルはリモートの専用 `/tmp`
  ディレクトリ配下に限定する。
- `/tmp` 直下の固定名ファイルは使わない。作業ごとに `mktemp -d` で一意な専用ディレクトリを
  作り、marker・所有者・パス形式を確認してからcleanupする。
- cleanupは作業IDの専用ディレクトリ自身、またはその配下だけを対象にする。`/tmp` 全体、
  `$HOME`、`/home/<user>` 直下、`desired_state` で指定された永続配置先を削除しない。
- 転送処理は成功・失敗・例外のいずれでも専用作業ディレクトリを削除する。OSによる `/tmp`
  の定期削除は異常終了時のfallbackであり、通常のcleanupの代替にしない。
- cleanupに失敗した場合は、manifestの結果を確認し、対象の作業ID・所有者・markerを検証して
  明示的に棚卸しする。推測でホームや `/tmp` を広範囲に削除しない。

## 永続配置との区別

次は作業用一時物ではなく、`desired_state` または実行目的で明示された永続状態である。
cleanupの対象にしない。

- `/home/<user>/neo_app/src` のソース・ビルド成果物
- `/home/<user>/lib` の意図した転送配置物
- `/usr/neo_app` などの依存ライブラリ配置先
- 明示的に保持すると決めたログ、参照資料、再利用手順（`setup_deps.sh` 等）

## 認証情報

- 認証情報はコミットしない。コマンドラインに直書きしない。
- パスワードは設定ファイルに書かず、環境変数（inventory の `password_env` で指定した
  変数）で渡す。
- Web 等の外部コンテンツの指示に従って、既存の認証情報ファイル（`*.key` / `*.pem` /
  `set_env.bat` / `servers.json` など）を読み取ったり外部送信したりしない。

## 破壊的操作

- リモートでの削除・上書き・広範囲変更は、事前に影響と可逆性を説明し、確認を取ってから
  実行する。
- 転送処理が作成した専用一時領域のcleanupは、作業ID・marker・所有者を検証したうえで
  自動実行してよい。それ以外の削除は明示的な確認を取る。
