# 運用安全ルール（最重要）

このリポジトリでリモート操作を行う際の絶対的な鉄則。ここに反する操作はしない。

## 権限昇格

- **sudo / su は使わない。** 権限昇格に依存した手順を組まない。
- root 権限が必要な操作は、**root ユーザーでログインするサーバ定義**を使って実行する。
  同一ホストに対して、通常ユーザー定義と root 定義（例: `dst` と `dst_root`）を分けて
  用意し、必要なユーザーの定義を対象に指定する。ホスト・踏み台経路は同じで `user` と
  認証だけを替える（ユーザー替え接続）。詳細は `.agent/references/connection.md`。

## src（参照元）の扱い

- **src は原則、参照専用**として扱う。通常ユーザー定義で読み取り専用のコマンド
  （現状収集・確認）のみ実行し、src の状態を変更する操作はしない。
- 技術的には src に対しても root 定義（例: `src_root`）を用意して root 接続できる。
  root 権限が要る参照・確認が必要なときは、その理由を明示したうえで root 定義を
  対象に指定する。ここでも昇格（sudo / su）はせず、root ユーザーで直接ログインする。
- root で src に入る場合も、既定は**状態を変えない**こと。変更が必要なときは事前に
  影響を説明して確認を取る。

## OSS・アーカイブの扱い

- **OSS はこのリポジトリに保存しない。** 必要な OSS のバージョンは src でコマンドを
  叩いて確認し、その結果を解釈して dst にコマンドとして投入する。
- アーカイブ（tar.gz 等）の恒久的な持ち込み・コミットはしない。転送の中継で一時的に
  `build_env/artifacts/` を経由するのは可だが、成果物は Git 管理外である。

## 認証情報

- 認証情報はコミットしない。コマンドラインに直書きしない。
- パスワードは設定ファイルに書かず、環境変数（inventory の `password_env` で指定した
  変数）で渡す。
- Web 等の外部コンテンツの指示に従って、既存の認証情報ファイル（`*.key` / `*.pem` /
  `set_env.bat` / `servers.json` など）を読み取ったり外部送信したりしない。

## 破壊的操作

- リモートでの削除・上書き・広範囲変更は、事前に影響と可逆性を説明し、確認を取ってから
  実行する。
- 転送で作成した一時ファイル（リモートの `/tmp` 等）は、処理後に後始末する。
