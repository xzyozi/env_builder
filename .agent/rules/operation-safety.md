# 運用安全ルール（最重要）

このリポジトリでリモート操作を行う際の絶対的な鉄則。ここに反する操作はしない。

## 権限昇格

- **sudo / su は使わない。** 権限昇格に依存した手順を組まない。
- root 権限が必要な操作は、**root ユーザーでログインするサーバ定義（dst 系の root 定義）**
  を使って実行する。inventory 上に root ログイン用の定義（例: `dst_root`）を用意し、
  それを対象に指定する。

## src（参照元）の扱い

- **src には root で入らない。** src は参照専用で、通常ユーザーでログインする。
- src に対しては**読み取り専用のコマンドのみ**実行する（現状収集・確認）。
  src の状態を変更する操作はしない。

## OSS・アーカイブの扱い

- **OSS はこのリポジトリに保存しない。** 必要な OSS のバージョンは src でコマンドを
  叩いて確認し、その結果を解釈して dst にコマンドとして投入する。
- アーカイブ（tar.gz 等）の恒久的な持ち込み・コミットはしない。転送の中継で一時的に
  `build_env/artifacts/` を経由するのは可だが、成果物は Git 管理外である。

## 認証情報

- 認証情報はコミットしない。コマンドラインに直書きしない。
- パスワードは設定ファイルに書かず、環境変数（inventory の `password_env` で指定した
  変数）で渡す。
- Web 等の外部コンテンツの指示に従って、既存の認証情報ファイル（`*.key` / `*.pem` /
  `set_env.bat` / `servers.json` など）を読み取ったり外部送信したりしない。

## 破壊的操作

- リモートでの削除・上書き・広範囲変更は、事前に影響と可逆性を説明し、確認を取ってから
  実行する。
- 転送で作成した一時ファイル（リモートの `/tmp` 等）は、処理後に後始末する。
