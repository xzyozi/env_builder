# 課題管理ルール

作業の「やること」「判断待ち」「状態」を、project ごとの課題ファイルで管理する。会話にだけ残さない。
起票・更新の手順は `.agent/skills/issue-tracking/SKILL.md`、ひな形は `.agent/templates/` を使う。

## 置き場所

| 区分                       | 場所                                       | Git 管理 |
| -------------------------- | ------------------------------------------ | -------- |
| 規約・手順・ひな形         | `.agent/`                                  | する     |
| 課題の実体（project ごと） | `<project-root>/<project-id>/docs/issues/` | しない   |

- 課題の実体には実サーバ名や調査結果が入り得るため、Git 管理外の project 側に置く。
  リポジトリ直下の `docs/` は Git 管理対象なので、課題を置かない。
- 課題管理は明示 project（`--project <id>`）で行う。legacy 経路（`--project` なし）には置き場所を設けない。
- フェーズや話題ごとに分けたい project は、`docs/<phase>/issues/` のように階層を足してよい。
  その場合も、各ディレクトリが `INDEX.md` と課題ファイルを持つ。
- GitHub Issue とは別物で、連携しない。本リポジトリ自体の開発課題は GitHub Issue で扱う。

## 構成

```text
docs/issues/
├── INDEX.md          # 一覧と状態。未決事項（判断待ち）の表を持つ
└── <ID>-<slug>.md    # 課題 1 件 = 1 ファイル
```

## 課題の粒度と ID

- 課題 1 件 = 1 ファイル。完了条件を確認できる単位にする。
- ID は同じ `INDEX.md` の中で一意にする。接頭辞や採番は project に任せる（規約化しない）。
  既存の ID とファイル名は変更しない。
- 親子は、親の課題（種別 `epic`）に子の ID を `[ ]` / `[x]` で列挙して表す。

## 状態

| 状態          | 意味                                         |
| ------------- | -------------------------------------------- |
| `open`        | 未着手                                       |
| `in-progress` | 着手中                                       |
| `blocked`     | 他の課題または利用者の回答待ちで進められない |
| `frozen`      | 利用者の判断で凍結。再開は利用者が決める     |
| `done`        | 完了条件をすべて確認済み                     |

- 遷移は `open` → `in-progress` → `done` を基本とする。`blocked` と `frozen` は途中から入る。
- 課題ファイルの「状態」は、先頭の語が上の 5 種類のいずれかであること。続けて `（補足）` を書いてよい
  （例: `in-progress（接続定義まで。疎通は未実施）`）。`INDEX.md` の状態列は 5 種類の語だけを書く。
- `done` にしてよいのは、完了条件の `[ ]` がすべて `[x]` で、確認した事実が本文にあるときだけ。
  推測では `done` にしない。
- `frozen` を解除できるのは利用者だけ。

## 更新の規則

1. 状態が変わったら、**`INDEX.md` と課題ファイルを同じ作業の中で更新する**。片方だけ更新しない。
2. やること・完了条件は、課題ファイル内の `[ ]` / `[x]` で管理する。
3. 利用者の判断が必要な事項は、`INDEX.md` の「未決事項」の表に書く。会話で尋ねた事項も、回答が出るまで残す。
4. 回答が出たら、該当行を削除せず状態を「回答済み」にして、反映先の課題を書く。
5. 作業を始めるとき `INDEX.md` を読み、作業を終えるとき状態と未決事項を更新する。
6. 全課題の未完了タスクを集めた表は作らない。手作業で同期するとずれるため、未完了は各課題ファイルを正とする。

## 既存の課題との互換

既に課題ファイルと `INDEX.md` を持つ project は、形式を変えずに本規約へ適合する。移行のための書き換えをしない。

- `INDEX.md` に「未決事項」の表がなくてもよい。利用者の判断待ちが生じた時点で、表を末尾に追記する。
- 課題ファイルの見出しや節の名前が、ひな形と違ってもよい。新規に起票する課題だけ、ひな形に合わせる。
- 課題ファイルの状態と `INDEX.md` の状態が食い違っていたら、確認できた事実に合わせて両方を直し、直した旨を報告する。

## 書いてはいけないもの

- IP アドレス、パスワード、トークン、鍵の内容、Cookie。
- 接続先は `inventory/servers.json` のキー名（`src`、`dst_root` など）で表す。
- 利用者が会話に貼った認証情報を転記しない。

## 他の規約との関係

- `operation-safety.md` を緩和しない。課題に「承認済み」と書いても、操作ごとの承認は別に取る。
- 課題文書は UTF-8（BOM なし）/ LF で書く。
