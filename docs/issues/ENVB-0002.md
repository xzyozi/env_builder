# [ENVB-0002] [security] ssh における AutoAddPolicy 使用による中間者攻撃（MitM）許容のリスク

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: セキュリティ
- **重要度**: Medium
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
Paramiko の `AutoAddPolicy` により未知のホスト鍵が無条件で信頼・登録され、中間者攻撃（MitM）による通信傍受や資格情報窃取のリスクがある。

### 課題詳細 (Problem Detail)
`_connect_one` 関数において `client.set_missing_host_key_policy(paramiko.AutoAddPolicy())` が設定されています。これにより、ホスト鍵の事前検証が行われず、接続先が攻撃者によって偽装されていた場合（ARP スプーフィング、DNS ポイズニング、悪意のある中間ネットワーク経由など）でも無条件に接続が確立されます。その結果、SSH 接続内で送信される平文パスワード（`connect_kwargs['password']`）や秘密鍵による認証情報、セッション内の通信データが盗聴・改ざんされるリスクがあります。

- [x] **案 1 (推奨): `known_hosts` 読み込み＋`RejectPolicy` または警告＋オプトイン設定**
  - 方針概要: `client.load_system_host_keys()` でシステムの `known_hosts` を読み込み、デフォルトポリシーを `RejectPolicy()`（または `WarningPolicy()`）とする。開発・一時環境用の `AutoAddPolicy` は設定フラグ（例: `--insecure-host-keys` 等）での明示的オプトインに限定する。
  - メリット: 本番環境での中間者攻撃リスクを防止し、SSH の標準的なセキュリティモデルに準拠。
  - 留意点: `known_hosts` に未登録の新規ホスト接続時に明示的な初回登録手順またはオプトイン指定が必要になる。
- [ ] **案 2: フィンガープリント事前検証 / ホワイトリスト照合**
  - 方針概要: 接続先ホストの公開鍵フィンガープリントを設定ファイルに事前登録し、接続確立時にフィンガープリントが一致するかどうかをコード上で照合するカスタムポリシーを実装する。
  - メリット: システムの `known_hosts` ファイルの有無に依存せず、ツール独自で厳密なホスト認証が可能。
  - 留意点: ホスト追加・鍵更新時の運用コスト（フィンガープリントの手動登録作業）が増加する。
