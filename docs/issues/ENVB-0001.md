# [ENVB-0001] [security] sync_tree における引数展開起因のリモートコマンドインジェクション脆弱性

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: セキュリティ
- **重要度**: High
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
コマンドライン引数（`--remote-src` および `--remote-dst-parent`）がエスケープされずにリモートシェルコマンド文字列に直接埋め込まれており、コマンドインジェクションが可能。

### 課題詳細 (Problem Detail)
`main` 関数内で受け取った引数 `args.remote_src` から導出される `parent`, `base`, `src_tar` および `args.remote_dst_parent` は、シェルエスケープ処理（`shlex.quote` 等）が行われないまま f-string 形式で `tar czf {src_tar} -C {parent} {base}` や `mkdir -p {args.remote_dst_parent} && tar xzf {dst_tar} ...` に展開されています。指定パスにシェルメタ文字（`;`, `&`, `|`, ` `, $(), 改行など）が含まれていた場合、リモートホスト上で任意の OS コマンドが実行されます。特に dst 側は root 権限（`dst_root`）での実行が想定されているため、root 権限での任意コード実行・システム侵害に直結します。

- [x] **案 1 (推奨): `shlex.quote` による引数エスケープの適用**
  - 方針概要: コマンド文字列組み立て箇所で、パスや引数変数（`parent`, `base`, `src_tar`, `dst_tar`, `args.remote_dst_parent` 等）をすべて `shlex.quote()` でエスケープする。
  - メリット: 既存のコマンド体系や実行フローを壊さず、最小限の変更でインジェクションを確実に防げる。高い互換性と安全性。
  - 留意点: コマンド文字列全体の構造はシェルのまま。
- [ ] **案 2: 入力引数の事前バリデーション（ホワイトリスト・文字種チェック）の追加**
  - 方針概要: パス引数にシェルメタ文字（`;`, `&`, `|`, ` `, $(), 改行など）が含まれていないか事前に正規表現や許可文字セットでバリデーションし、違反時は即座にエラー停止する。
  - メリット: 想定外の危険な入力を入口で完全に遮断できる多層防御。
  - 留意点: 正当な空白や一部特殊文字を含むパスを過剰に弾く可能性がある。
