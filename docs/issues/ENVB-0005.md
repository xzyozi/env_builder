# [ENVB-0005] [design] 作業用一時領域と終了時cleanupを統一

## 背景

作業用の `.sh`、転送用 tar、検証ログ、一時ファイルが作業終了後も残り、次の問題がある。

- 作業終了後に一時物を回収するライフサイクルが、スクリプトの処理フローに組み込まれていない。
- `/home/<user>` 直下や `/tmp` 直下に作業ファイルが散在し、永続配置物との区別が難しい。
- `build_env/artifacts` に再利用手順、適用スクリプト、調査スクリプト、検証スクリプト、転送取得物、参照資料が羅列され、保持対象とcleanup対象が見分けにくい。
- 既存の作業用 `.sh` を単純に削除することが目的ではない。今後の作業で不要な残置物を発生させないことが目的である。

## 決定済みの方針

### リモート作業領域

- `/home/<user>` 直下は作業場所として使用しない。直下へのファイル作成・削除を禁止する。
- `/tmp` の利用は許可する。OS側の定期削除は補助的なfallbackとし、作業終了時の明示的なcleanupを主経路とする。
- `/tmp` 直下に固定名のファイルを作らず、作業ごとに一意な専用ディレクトリを作る。
- 作業ファイルは専用ディレクトリ配下に限定する。例:

  ```text
  /tmp/env_builder-<work-id>/
  ├── marker
  ├── stage/
  └── logs/
  ```

- cleanupは作業ディレクトリ単位、またはその配下だけを対象にする。`/tmp` 全体、`$HOME`、
  `/home/<user>` 直下、目的外の永続配置を削除対象にしない。
- 作業ディレクトリは作業開始時に所有者・権限・markerを確認し、作業終了時に成功・失敗を問わず削除する。通信断やプロセス強制終了で残ったものは、所有者・marker・期限を確認した明示的な棚卸しで扱う。

### 永続配置との分離

次のような `desired_state` で明示された配置先は、作業cleanupの対象にしない。

- `/home/<user>/neo_app/src` のソース・ビルド成果物
- `/home/<user>/lib` の意図した転送配置物
- `/usr/neo_app` の依存ライブラリ
- `setup_deps.sh` など再利用する手順書・スクリプト
- 調査・再現のため明示的に保持すると決めたログや参照資料

### ローカル成果物の分類

`build_env/artifacts` は用途別に分類する。既存ファイルは直ちに削除せず、今後作成するものから分類を適用する。

- `reusable/`: 再利用手順（`setup_deps.sh` 等）
- `patches/`: 適用・修正用スクリプト
- `diagnostics/`: 調査用スクリプト
- `verification/`: 検証用スクリプト
- `references/`: 作業実績・参照資料
- `transfers/`: 明示的に保持する取得物
- 作業中だけ必要な中継物: 作業ID付きのローカル作業領域。終了後にディレクトリごと削除

## 対象範囲

優先順位は次の通り。

1. `scripts/sync_tree.py`: src/dstの一時tarを専用作業ディレクトリへ集約し、成功・失敗・例外時にcleanupする。
2. `scripts/sync_files.py`: `file_000`等の匿名中継物を作業ID付き作業領域へ移し、転送終了後にcleanupする。
3. `scripts/core` に作業ID・専用作業領域・manifest・cleanup結果を扱う共通の仕組みを置く。
4. `remote_exec.py` / `run_build.py` のログと作業IDを関連付ける。ただし任意コマンドの副作用やビルド成果物を推測して自動削除しない。
5. 既存の作業用 `.sh` は、用途と継続利用の有無を確認してから分類・移行する。`setup_deps.sh` は必須のため保持する。

## 既存Issueとの関係

- #3 は予測可能な `/tmp` ファイル名やシンボリックリンク攻撃を含む安全な一時ディレクトリ生成の課題。
- 本Issueは、作業場所の規約、作業単位のcleanup、永続配置との分離、成果物分類を扱う。実装時は #3 の安全条件を満たす。

## 完了条件

- [ ] `/home/<user>` 直下に新規作業ファイルを作らない。
- [ ] `/tmp` 直下の固定名ファイルを使わず、作業ごとの専用ディレクトリを使う。
- [ ] 作業終了時に専用ディレクトリを成功・失敗の両方で削除する。
- [ ] cleanup対象が作業ID配下に限定され、永続配置を削除しない。
- [ ] cleanup失敗や強制終了で残った作業ディレクトリを安全に識別できる。
- [ ] `sync_tree.py` / `sync_files.py` の中継物が作業終了後に残らない。
- [ ] `build_env/artifacts` の新規成果物が用途別に分類される。
- [ ] `setup_deps.sh` を保持したまま、作業用一時物だけをcleanupできる。

## 未決定事項

- 専用ディレクトリ名を `/tmp/env_builder-<work-id>/` とするか、`/tmp/env_builder/<work-id>/` とするか。
- `/tmp` のOS側cleanupに任せる期限と、明示的な棚卸しコマンドのインターフェース。
- `--keep-workdir` のような失敗解析用の保持オプションを設けるか。
