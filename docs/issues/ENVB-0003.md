# [ENVB-0003] [security] sync_tree における /tmp 配下の予測可能なファイル名使用によるシンボリックリンク攻撃のリスク

## 0. メタ情報 (Scope & Impact)
- **検出テーマ**: セキュリティ
- **重要度**: Medium
- **関連Issue**: 該当なし
- **起票ステータス**: `stage:ideation` (agys 自律レビュー起票)

## 1. 概要・背景
共有ディレクトリ `/tmp` 直下に秒単位タイムスタンプのみに基づく予測可能なファイル名で一時アーカイブを作成しており、シンボリックリンク攻撃や競合状態のリスクが存在する。

### 課題詳細 (Problem Detail)
リモートの src および dst 上で作成・転送される一時ファイルが `src_tar = f"/tmp/{tar_name}"`（`tar_name = f"envb_{base}_{ts}.tar.gz"`）のように固定・予測可能な命名規則になっています。誰でも書き込み可能な共有ディレクトリ `/tmp` において、同一ホスト上の悪意あるユーザーが同一ファイル名のシンボリックリンクをあらかじめ重要ファイル（例: システム設定ファイル等）に向けて作成していた場合、root 権限で実行される `tar czf` や `put_file` によって既存ファイルが意図せず上書き・破壊される恐れがあります。

- [x] **案 1 (推奨): `mktemp -d` / ランダムサフィックス付き安全な一時ディレクトリの作成**
  - 方針概要: `mktemp -d /tmp/envb_XXXXXX` や Python の `tempfile` / `secrets` を用いてパーミッション `0700` のランダム一時ディレクトリを作成し、その配下にアーカイブを生成・転送・展開後、`finally` で確実に削除する。
  - メリット: 予測不可能性を担保し、他ユーザーによる事前シンボリックリンク配置や競合を確実に排除。Unix標準のセキュアな一時ファイル処理。
  - 留意点: 一時ディレクトリの作成・削除コマンドの管理が1ステップ増える。
- [ ] **案 2: プロジェクトローカルまたはユーザー専有ディレクトリ配下の利用**
  - 方針概要: 全体共有の `/tmp` を使わず、ユーザーのホームディレクトリ配下（`~/.cache/env_builder/tmp/` など、パーミッション `0700` で保護された領域）を作業領域とする。
  - メリット: 他ユーザーから完全に隔離されたディレクトリを利用するため、ファイル名が予測可能であっても安全性が高い。
  - 留意点: リモートホスト上に専用ディレクトリが存在するか確認・作成する必要があり、クォータ制限等に注意が必要。
