# [ENVB-0006] [bug] SSH実行の無応答とユーザー中断の未対応

## 概要
SSH経由の長時間処理について、接続timeoutとkeepaliveは実装済みですが、無応答とユーザー中断を安全に扱う仕組みが不足しています。

## 確認した現状
- `scripts/core/ssh.py` の `SSHSession.run()` は `stdout.read()` 完了後に `stderr.read()` を行うため、stdout/stderrを並行排出していません。
- `exec_command(timeout=...)` にはtimeoutを渡していますが、独立したwall-clock監視、timeout時のchannel close、リモートプロセス停止、timeout状態の明示的な結果表現はありません。
- `get_file()` / `put_file()` のSFTP転送には明示的なtimeoutがありません。
- `run_build.py` はリモートコマンド完了後にstepログを書き出すため、実行中の進捗とハングを区別できません。
- `KeyboardInterrupt`、SIGINT/SIGTERM、cancel API、リモートPID／プロセスグループ管理はありません。
- `with` / `finally` によるSSH接続・一時領域cleanupはありますが、接続を閉じてもリモートプロセス停止は保証されません。
- `SSHSession.__enter__()` の接続途中で中断した場合、途中まで作成された接続のcleanupが保証されない可能性があります。

## 再現・検証候補
許可された検証先で、次を確認する。

```powershell
uv run python scripts/remote_exec.py --target dst --timeout 3 -- "sleep 10"
```

```powershell
uv run python scripts/remote_exec.py --target dst --timeout 60 -- "sleep 30"
```

2つ目の実行中にCtrl+Cを押し、次を確認する。

1. ローカルCLIが確実に終了するか
2. `SSHSession` と踏み台接続が閉じるか
3. リモートの `sleep` が残らないか
4. キャンセル状態と原因がログに残るか
5. 実行中stepのstdout/stderrが失われないか

大量stderrによる詰まりを確認するため、ログ汚染を避けられる検証環境でstderr大量出力ケースも確認する。

## 期待する動作
- stdout/stderrを同時に排出し、大量出力でも処理が停止しない。
- timeoutがローカルCLIの応答保証だけでなく、channelの明示的な終了とリモート処理停止まで扱う。
- Ctrl+C／SIGTERMをキャンセルとして扱い、接続・一時領域をcleanupする。
- 可能な範囲でリモートの子プロセス／プロセスグループを停止する。
- timeout、cancel、接続失敗、通常終了をログと戻り値で区別する。
- SFTP転送にもtimeoutと中断時cleanupを適用する。
- モックまたは許可された統合テストで、無出力長時間処理・大量stderr・timeout・Ctrl+Cを再現できる。

- [ ] コマンドtimeout時にローカル処理が戻り、状態が明示される
- [ ] timeout／Ctrl+C時のSSH接続と専用一時領域のcleanupを確認できる
- [ ] リモートプロセス停止の成否と限界を仕様化する
